Apache Axis2 2.0.3 Release Notes
--------------------------------

(Unreleased)

## Upgrading from 2.0.2

| Change | Restore the old behaviour with |
|---|---|
| The JSON dispatcher no longer selects a service from the XML body namespace | `<parameter name="allowContentBasedServiceDispatch">true</parameter>` |
| `enableJSONOnly` refuses non-JSON GET, PUT and DELETE requests as it does POST | no switch; send `Content-Type: application/json` |

`JSONBasedDefaultDispatcher`, the Dispatch-phase dispatcher in the Spring Boot
starter's `axis2-json.xml`, now honours `allowContentBasedServiceDispatch` as the
SOAP body dispatchers have since 2.0.2. JSON-RPC requests are unaffected, since their
service comes from the request URI. A deployment that posted `application/xml` to a
URI naming no service, relying on the root element's namespace to pick the service,
now gets a service-not-found fault until the parameter is set. Set it only if
services are genuinely addressed that way, and not alongside per-service security
modules.

`enableJSONOnly` was only enforced for POST. A GET, PUT or DELETE, and on the
standalone server a POST with an XML or form content type, took the REST path, which
bound the operation's arguments from the query string or an XML body and invoked it.
Those requests are now refused unless they carry `Content-Type: application/json`.
Metadata requests (`?wsdl`, `?xsd`, the service listing) are unaffected.
